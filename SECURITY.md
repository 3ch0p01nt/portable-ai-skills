# Security Policy

## Reporting a vulnerability

Report suspected vulnerabilities privately through GitHub Security Advisories for this repository. Include a minimal reproduction, affected files or versions, and impact. Do not open a public issue for an unpatched vulnerability.

Never post real incident evidence, device configurations, support bundles, credentials, keys, tokens, customer identifiers, private addresses, topology, or other secrets in an issue, pull request, discussion, or test fixture. Use synthetic and redacted examples only.

The maintainers will acknowledge a report, assess scope, coordinate a fix, and publish appropriate remediation after affected users can act.

## Scope

Security reports may cover the skill instructions, local parsers/analyzers, validation scripts, schemas, or unsafe handling of untrusted evidence. Cisco product vulnerabilities should be reported to Cisco PSIRT through Cisco's official process.

This repository is for authorized defensive use. Its Cisco tooling operates on local artifacts and must never be used to connect to live devices.
